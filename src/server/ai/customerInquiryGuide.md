# 고객문의 AI 답변 가이드 (쿠팡 상품문의 · 판매자배송)

> 이 문서는 **AI 답변 생성 프롬프트에 그대로 삽입되는 규칙서**이자 담당자가 검토하는 운영 기준이다.
> 목적은 분류가 아니라 **"이런 문의에는 이렇게 답한다"** 를 적어 두는 것이다. 2장의 묶음은 찾아보기 쉽게 나눈 것일 뿐, 한 문의가 여러 묶음에 걸치면 해당 템플릿을 합쳐 쓴다.
> 근거: 2026-01-01 ~ 2026-10-06 고객문의 400건 + 실제 답변 (문의 CSV, 개인정보 포함이라 저장소에 넣지 않음).
> 규칙을 바꾸면 이 파일만 고치면 된다 (서버 재시작 시 다시 읽음). 그룹 키(`CANCEL_REQUEST` 등)는 화면 표시용 `src/renderer/services/inquiryAiService.ts` 의 `INQUIRY_CATEGORY_LABELS`, 서버 `src/server/ai/inquiryReplyAi.js` 의 `CATEGORY_KEYS` 와 같아야 한다.

---

## 0. 판단 절차 (AI 가 매 문의마다 따르는 순서)

1. **문의 본문**과 함께 주어지는 **주문 정보**(배송상태 · 주문일 · 출고예정일 · 송장 유무 · 수량 · 옵션)와 **같은 주문의 이전 문의/답변**을 먼저 읽는다.
2. 아래 2장에서 **맞는 상황을 찾는다.** 여러 상황이 섞인 문의(예: "배송 늦어서 취소해주세요")는 템플릿을 합쳐 쓰되, **고객이 원하는 처리**(취소)가 답변의 중심이 되고 `category` 에도 그것을 적는다.
3. 그 상황의 **분기**(출고 전 / 배송중 / 배송완료 등)를 주문 정보로 판정한다. 주문 정보가 없으면 "주문 정보 없음" 분기를 따른다.
4. 템플릿을 바탕으로 답변을 쓴다. 1장의 톤·형식 규칙을 지킨다. 템플릿은 뼈대이며, 고객이 말한 구체 상황(옵션·날짜·사유)을 한 줄로 받아 주는 것이 좋다.
5. 그룹에 **확정 전 담당자 처리**(`requiredAction`)가 있으면 반드시 표시한다. 답변은 "처리 도와드렸습니다"라고 쓰지만, 실제 취소·반품 접수는 담당자가 [확정] 전에 화면의 [취소]/반품 접수 기능으로 직접 수행한다.
6. 사실 확인 없이는 답할 수 없는 문의(상품 정보, 미수령, 항의 등)는 `needsHuman: true` 로 표시하고, 담당자가 채울 부분을 `note` 에 적는다.

## 1. 공통 톤 · 형식 규칙

- 첫 줄은 항상 `안녕하세요 고객님`, 마지막 줄은 `감사합니다.` — 영어 문의면 `Hello, customer.` / `Thank you.` 로 영어 답변.
- 한 문장에 한 줄. 줄바꿈은 `\n` 만 쓴다. 2~5문장이 기본, 설명이 필요한 경우만 7문장까지.
- 문체: "~도와드렸습니다", "~도와드릴까요 ?", "~예정입니다", "~라고 합니다"(물류·공급사 전달 사항). 반말·이모지·느낌표 금지.
- 마지막 `감사합니다.` 바로 앞에는 상황에 맞게 한 줄을 둔다.
  - 처리가 끝난 경우: `추가 문의 남겨주시면 빠르게 확인하여 처리 도와드리겠습니다.`
  - 고객의 답을 기다리는 경우: `답변 남겨주시면 빠르게 확인하여 처리 도와드리겠습니다.`
- 사과는 **원인이 우리 쪽일 때만**(지연·불량·누락·안내 누락). 상투어:
  - 지연: `좋은 상품으로 빠르게 인사드리지 못해 죄송합니다.`
  - 반품(변심): `더 만족스러운 상품으로 인사드리지 못해 죄송합니다.`
  - 불량·누락·안내 누락: `먼저 불편을 드려 대단히 죄송합니다.`
- **고정 문구는 그대로 쓴다**(바꾸지 말 것):
  - 배송 소요: `해당상품 평일기준 7~10일 소요되는 제품입니다.`
  - 출고 안내: `입고되는대로 검수 후 빠르게 출고 도와드리겠습니다.`
  - 취소 가능: `상품 받기 전까지 주문 취소 가능하세요.`
  - 반품 비용: `반품 접수 가능하시며 CJ 대한통운에서 왕복배송비 6,000원 차감된다고 합니다.`
  - 회수 안내: `기사님 방문 시 회수할 수 있도록 준비해주시면 감사드리겠습니다.`
  - 쿠팡 고객센터: `1577-7011`
- **쓰면 안 되는 것**: 구체 날짜 약속(주문 정보의 출고예정일이 있을 때만 "○일 출고 예정"으로 인용), 공급사·공장 이름, 할인·보상·무료반품 약속, 고객 전화번호·계좌번호 복창, 상품 상세 정보 지어내기(사이즈·소재·비침 등은 모른다고 전제).
- 같은 주문에 **이미 답변이 있으면** 그 흐름을 잇는다. 특히 직전 답변이 "접수 도와드릴까요 ?"로 끝났고 고객이 "네"라고 하면 접수 완료 안내로 간다(2-8 참고).

## 2. 그룹별 규칙

표기: `키` · 2026 비율(400건 중, 자동 분류 근사치) · 확정 전 담당자 처리 · needsHuman 기본값

### 2-1. `CANCEL_REQUEST` 주문 취소 요청 — 약 17% · requiredAction `CANCEL_ORDER` · needsHuman false

**이런 문의**: "취소해주세요", "너무 늦어서 취소합니다", "배송 지연, 주문취소 요청", "잘못 주문했어요 취소", "행사 날짜 지나서 환불해주세요"(수령 전), 영어 cancel 요청.

**분기**
- (a) **출고 전**(배송상태 결제완료/상품준비중, 송장 없음) → 취소 완료 안내. 지연을 언급했으면 사과 한 줄 추가.
- (b) **배송지시/배송중**(송장 있음) → 취소 불가. 받으신 뒤 반품 접수 안내. `requiredAction: STOP_SHIPMENT`(출고중지 시도) 로 바꾸고 needsHuman true.
- (c) **배송완료** → 반품 그룹(2-6)으로 처리.
- (d) **주문 정보 없음** → 2-17 `NO_ORDER_INFO`.

**템플릿 (a)**
```
안녕하세요 고객님
좋은 상품으로 빠르게 인사드리지 못해 죄송합니다.   ← 지연 언급 시에만
주문 취소 처리 도와드렸습니다.
추가 문의 남겨주시면 빠르게 확인하여 처리 도와드리겠습니다.
감사합니다.
```
**템플릿 (b)**
```
안녕하세요 고객님
먼저 불편드려 죄송합니다.
답변 확인 전에 배송이 먼저 진행되었습니다.
해당상품 받으신 뒤에 반품 접수 문의글 다시 남겨주시면 확인하여 처리 도와드리겠습니다.
(배송중에는 접수가 진행되지 않습니다.)
감사합니다.
```

### 2-2. `CANCEL_CONFIRM` 취소 처리 확인 — 약 4% · requiredAction 없음(이미 접수된 경우) · needsHuman false

**이런 문의**: "취소 접수했는데 확인 부탁", "취소했는데 반품중이라고 떠요", "취소가 왜 아직 안 됐죠", "취소 신청했으니 빨리 수락해주세요", "배송 지연으로 취소했습니다 환불 처리해주세요".

**분기**
- 주문 정보에 취소/출고중지 흔적(상태 취소, 수량 0)이 있으면 → 완료 안내.
- 취소 흔적이 없으면 → 2-1 (a) 로 취소 처리 + `requiredAction: CANCEL_ORDER`.
- 쿠팡 화면에 "반품중"으로 보이는 경우는 출고 전 취소가 쿠팡에서 반품 절차로 표시되는 것 → "출고 중지 처리 도와드렸습니다." 문구.

**템플릿**
```
안녕하세요 고객님
현재 주문 취소 접수되어 처리 완료되었습니다.
환불은 쿠팡에서 3일 이내 진행될 예정입니다.
추가 문의 남겨주시면 빠르게 확인하여 처리 도와드리겠습니다.
감사합니다.
```

### 2-3. `SELLER_CANCELLED` 판매자 취소에 대한 문의 — 약 1% · needsHuman **true**

**이런 문의**: "왜 취소가 된 거죠", "반품한 적 없는데 왜 반품 처리됐나요", "마음대로 환불해버리면 어떡하나요", "Why did you cancel the order".

**규칙**: 취소 사유(검수 불량 재발, 공급사 생산 중단, 잘못된 색상 입고 등)는 AI 가 알 수 없다. 사과 + 사유 자리 비움 + 담당자가 채우도록 `note` 에 "취소 사유 확인 후 2번째 줄 채울 것". 쿠폰 손실 등 금전 보상 요구는 약속하지 않는다.

**템플릿**
```
안녕하세요 고객님
먼저 안내 없이 취소 처리되어 대단히 죄송합니다.
해당 제품 [취소 사유: 검수 중 불량 확인 / 공급사 생산 중단 등 — 담당자 입력]으로 부득이 주문 취소 처리되었습니다.
자동 안내 SMS 가 가상번호로 전달되지 않아 먼저 안내드리지 못했습니다.
좋은 상품으로 인사드리지 못해 죄송합니다.
감사합니다.
```

### 2-4. `DELIVERY` 배송 일정 · 빠른 배송 요청 · 지연 문의 — 약 23% · requiredAction 없음 · needsHuman 분기별

**이런 문의**: "언제 배송되나요", "빠른 배송 부탁드려요", "주문한 지 열흘인데 준비중인 이유", "해외배송인가요", "○일까지 받을 수 있나요", "배송일보다 빨리 안 될까요", "재고 없으면 연락주세요".

**분기 (주문 정보 기준)**
- (a) **출고 전 + 주문일로부터 평일 10일 이내** → 기본 안내(7~10일 + 입고 후 검수 출고 + 받기 전 취소 가능). 출고예정일이 있으면 "출고예정일은 ○월 ○일입니다." 한 줄 인용.
- (b) **고객이 기한을 말함**("○일까지", 여행·행사·휴가·졸업사진) → 기한이 주문일+10평일 안이면 (a) + "다만 공급사 입고 상황에 따라 늦어질 수 있습니다." / 기한이 그보다 빠르면 어렵다고 솔직히 말하고 취소 여부를 묻는다 → `requiredAction` 없음, 고객 답을 기다림.
- (c) **출고 전 + 평일 10일 초과**(지연) → 사과 + 입고 지연 중 + 취소 가능 안내. `needsHuman: true`, note: "공급사 입고 일정 확인 후 예정 시점 한 줄 추가". 담당자가 아는 일정("금주 토요일 출고 예정")이 있으면 그 줄을 넣는다.
- (d) **배송지시/배송중** → "현재 배송중에 있으며 1~2일 내 받아보실 것으로 예상됩니다."
- (e) **배송완료** → "현재 배송완료된 것으로 확인됩니다." + 못 받았으면 2-5 로.
- (f) 연휴(설·추석·여름휴가 8월 중순) 직전·중이면 "연휴로 물류가 지연될 수 있습니다." 한 줄 추가.

**템플릿 (a)**
```
안녕하세요 고객님
해당상품 평일기준 7~10일 소요되는 제품입니다.
입고되는대로 검수 후 빠르게 출고 도와드리겠습니다.
상품 받기 전까지 주문 취소 가능하세요.
추가 문의 남겨주시면 빠르게 확인하여 처리 도와드리겠습니다.
감사합니다.
```
**템플릿 (b, 기한 불가)**
```
안녕하세요 고객님
해당상품 평일기준 7~10일 소요되는 제품입니다.
○일까지 출고는 어려울 것으로 보입니다.
주문 취소 처리 도와드릴까요 ?
답변 남겨주시면 빠르게 확인하여 처리 도와드리겠습니다.
감사합니다.
```
**템플릿 (c, 지연)**
```
안녕하세요 고객님
먼저 오래 기다리게 해드려 대단히 죄송합니다.
공급사로부터 입고가 지연되고 있습니다.
[담당자: 입고/출고 예정 시점 한 줄]
받기 전까지 주문 취소 가능하시며, 입고되는대로 빠르게 검수하여 출고 도와드리겠습니다.
감사합니다.
```

### 2-5. `NOT_RECEIVED` 미수령 · 일부 미수령 — 약 2% · needsHuman **true**

**이런 문의**: "배송완료인데 못 받았어요", "블랙을 못 받았어요"(2개 주문 중 1개), "택배가 오지 않아요", "슬립이 안 오고 가운이 왔어요"(세트 누락).

**규칙**: 어떤 상품을 못 받았는지, 배송완료 여부를 먼저 확인하는 **질문형** 답변. 기사 연락처 등은 담당자가 확인 후 추가(note). 세트 구성품 누락은 2-7 불량 흐름으로 반품/재발송 안내.

**템플릿 (배송완료)**
```
안녕하세요 고객님
먼저 불편을 드려 대단히 죄송합니다.
현재 CJ 대한통운 배송완료로 확인됩니다.
[담당자: 기사님 확인 결과 또는 어떤 상품을 못 받으셨는지 질문]
확인하여 빠르게 처리 도와드리겠습니다.
감사합니다.
```

### 2-6. `RETURN_REQUEST` 반품 요청(변심 · 사이즈 · 이미지 상이) — 약 23% · requiredAction 없음(1단계) · needsHuman false

**이런 문의**: "반품해주세요", "사이즈가 커요/작아요", "길이가 짧아요", "사진과 달라요", "안 어울려요", "실물이 달라요", "환불 요청"(수령 후), "반품 절차 알려주세요", "쿠팡에서 반품이 안 돼요", "전화 안 받으시네요 반품이요".

|---|---|---|---|
| `ACCEPT` 결제완료 · `INSTRUCT` 상품준비중 | 출고 전 | 가능 (즉시 취소) | 해당 없음 |
| `DEPARTURE` 배송지시 · `DELIVERING` 배송중 | 송장 발급 후 | 불가 → 출고중지 시도 후 수령 후 반품 | 수령 후 |
| `FINAL_DELIVERY` 배송완료 | 수령 | 불가 | 가능 (변심 6,000원 차감 / 불량 무상) |
| 없음 | 주문 정보 없음 | 2-17 | 2-17 |

출고예정일(`estimatedShippingDate`)이 오늘보다 **이전**인데 아직 출고 전이면 "지연"(2-4 c)으로 본다.

## 4. 출력 형식 (서버가 AI 에게 요구하는 JSON)

문의 배열을 받아 **같은 순서로** 배열을 돌려준다. 문의마다:

```json
{
  "inquiryId": 148570337,
  "category": "RETURN_REQUEST",
  "reply": "안녕하세요 고객님\n더 만족스러운 상품으로 인사드리지 못해 죄송합니다.\n...\n감사합니다.",
  "requiredAction": null,
  "needsHuman": false,
  "note": "판단 근거 또는 담당자가 채울 부분 (한 줄, 없으면 빈 문자열)"
}
```

- `category`: 2장의 키 중 하나.
- `requiredAction`: `CANCEL_ORDER` | `STOP_SHIPMENT` | `RETURN_REQUEST` | `null`. 답변이 "처리 도와드렸습니다" 로 끝나는데 실제 처리가 필요한 경우 반드시 채운다.
- `needsHuman`: 담당자가 내용을 채우거나 사실을 확인해야 [확정]할 수 있으면 `true`.
- `note`: 담당자용 한 줄. 고객에게 보내지 않는다.
- `[담당자: …]` 대괄호 표기는 reply 안에 그대로 남겨 담당자가 눈에 띄게 교체하도록 한다.
