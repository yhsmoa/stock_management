# 일반판매자 상품 — 상품 수정 기능 계획 (2026-10-20)

> 대상: `/coupang` (채널 › 쿠팡관리 › 일반판매자 상품). 쿠팡 Open API 로 바꿀 수 있는 모든 항목을 화면에서 수정한다.
> 근거: 쿠팡 개발자 문서 조사 (2026-10-20) — 상품 수정(승인필요) · 상품 수정(승인불필요, partial) · 로켓그로스/하이브리드 상품 수정 · 옵션별 가격/재고/판매상태/기준가.

## 0. 수정 항목은 쿠팡 규칙에 따라 세 묶음으로 나뉜다

| 묶음 | 항목 | API | 반영 | 단위 |
|---|---|---|---|---|
| **A. 즉시 반영 (옵션)** | 판매가 · 할인율 기준가 · 재고 · 판매 중지/재개 | `vendor-items/{옵션ID}/…` (이미 프록시 있음) | 승인 없이 바로 | 옵션 |
| **B. 즉시 반영 (상품 배송)** | 배송비 종류·금액·조건부 무료 금액 · 배송방법 · 택배사 · 반품배송비(편도) · 출고지·반품지 코드 · 출고 소요일 · 도서산간 가능 · 묶음배송 | `PUT seller-products/{id}/partial` (**프록시 신규**) | 승인 없이 바로. **임시저장·승인대기 상품은 불가** | 상품 (하이브리드는 일반 쪽만) |
| **C. 재승인 필요 (상품 전체)** | 노출상품명 · 등록상품명 · 브랜드 · 제조사 · 검색태그 · 판매기간 · 인당 최대구매수량/기간 · 옵션명 · 바코드 · 모델번호 · 업체상품코드 | `PUT seller-products` (전체 JSON · **프록시 신규**) | 쿠팡 승인 뒤 반영 | 상품 (옵션 항목도 상품 전체를 보낸다) |
| 변경 불가 | 카테고리 · 상품상태(새상품/중고) · 묶음정보 · 승인 이력 있는 옵션 삭제 | 없음 | — | 화면에 "변경 불가" 표시만 |
| 보류 | 대표이미지·상세 이미지 · 상세 콘텐츠(HTML) · 고시정보 | C 와 같은 API | 재승인 | 편집기가 커서 이번 범위에서 뺀다 (아래 §6) |

C 묶음의 핵심 규칙: **상품 조회(GET) 응답 전문을 받아 바꿀 칸만 고친 뒤 통째로 다시 보낸다(PUT)**. 그래서 저장 직전에 반드시 최신 상세를 다시 받는다. 하이브리드 상품은 로켓그로스용 응답 모양(`marketplaceItemData`/`rocketGrowthItemData`)이 그대로 오므로, 받은 모양 그대로 돌려보내면 된다.

## 1. 화면 설계

### 1-1. 목록 옵션 줄 — A 묶음을 칸 클릭으로 바로 수정
- **판매가 · 기준가 · 재고** 칸: 클릭 → 숫자 입력 → Enter 적용 / Esc 취소. 적용 중 스피너, 실패하면 값 되돌리고 사유 표시.
  - 판매가: 10원 단위 정리, 현재가 대비 -50% ~ +100% 밖이면 "강제 적용" 확인을 한 번 더 받는다 (기존 모달과 같은 규칙).
  - 기준가: 0원부터 10원 단위.
  - 재고: 0 이상 정수.
- **판매상태 칩**: 클릭 → "판매 중지할까요?" 확인 → 적용. 쿠팡 모니터링으로 중지된 건은 재개가 안 되므로 실패 사유를 그대로 보여 준다.
- 여러 옵션 한꺼번에 바꾸는 **기존 선택 모달은 그대로 둔다** (칸 편집은 1건용).
- 승인완료가 아닌 상품(승인대기·반려·임시저장)의 옵션은 칸 편집을 막고 이유를 툴팁으로.

### 1-2. 상품 상세 패널 — "보기" 와 "수정" 두 모드
패널을 열면 **최신 상세를 쿠팡에서 바로 받는다** (지금은 저장된 행으로만 그림). 수정 모드는 이 최신 전문을 기준으로 한다.

- **배송·반품 (B 묶음)**: 폼 (배송비 종류 드롭다운 · 금액 · 조건부 무료 금액 · 배송방법 · 택배사 · 반품배송비 · 출고지/반품지 · 출고 소요일 · 도서산간 · 묶음배송) → [즉시 적용]. 하이브리드는 "일반 옵션에만 적용" 안내. 임시저장·승인대기면 폼을 잠그고 이유 표시.
- **상품 정보 (C 묶음)**: 노출상품명 · 등록상품명 · 브랜드 · 제조사 · 검색태그(칩, 20자·20개) · 판매기간. 칸을 고치면 "변경됨" 표시가 쌓인다.
- **옵션 표 (C 묶음)**: 옵션명 · 바코드 · 모델번호 · 업체상품코드 · 인당 최대구매수량/기간 칸 클릭 편집. 하이브리드는 일반/로켓 값이 따로라 채널별로 칸이 나뉜다. 로켓그로스 바코드는 **입고 이력이 있으면 잠근다**.
- 하단 [쿠팡에 수정 요청] 버튼: 바뀐 칸 목록을 확인 창에 보여 주고 → 최신 상세 GET → 바뀐 칸만 덮어쓰기 → PUT (승인 요청 포함) → 성공하면 상품 승인상태를 '승인대기중'으로 바꾸고 그 상품 상세를 다시 받는다.
  - 확인 창 문구: "쿠팡 승인 뒤에 반영됩니다. 승인대기 중에는 배송·반품 정보를 바꿀 수 없습니다."
- 변경 불가 항목(카테고리 등)은 회색으로 보여 주기만 한다.

### 1-3. 기록
- 쿠팡 적용이 성공한 옵션/상품만 DB 를 고치고 `app_changed_at` 을 찍는다 (기존 규칙).
- C 묶음은 DB 값이 아니라 쿠팡 승인 뒤 값이 바뀌므로, 저장 성공 직후 그 상품만 상세 받기를 다시 돌려 DB 를 맞춘다.

## 2. 서버 (개발 `coupangProxy.ts` · 운영 `prodServer.js` **양쪽**)

| 경로 | 쿠팡 | 용도 |
|---|---|---|
| `PUT /api/coupang/seller-product-partial` | `PUT …/seller-products/{id}/partial` | B 묶음. body 의 허용 필드만 통과시킨다 |
| `PUT /api/coupang/seller-product` | `PUT …/seller-products` | C 묶음. body = 상품 전문 (`requested` 포함) |
| `PUT /api/coupang/seller-product-approval` | `PUT …/seller-products/{id}/approvals` | 자동 승인요청을 안 쓸 때의 보조 |

기존 `GET /api/coupang/rg-product/:id` 가 상세 조회(GET→PUT 의 GET) 로 그대로 쓰인다. 옵션별 가격·재고·상태·기준가 프록시도 이미 있다.

## 3. 데이터
- **새 DB 칼럼 없음.** 수정 모드는 매번 쿠팡 최신 전문을 받아서 쓰므로 브랜드·제조사·검색태그·판매기간·모델번호를 DB 에 둘 필요가 없다. (DB 변경 권한도 지금 막혀 있다.)
- 승인상태는 저장 성공 시 `coupang_approval = '승인대기중'` 로 고치고, 이후 [판매상태 확인]·엑셀·상세 받기가 실제 값으로 덮는다.

## 4. 코드 배치 (기존 분리 패턴)
- `services/coupangProductService.ts`: `fetchProductDetailLive(id)` · `applyPartialUpdate(id, fields)` · `submitProductModification(id, edits)` (GET→머지→PUT) · 옵션 1건용 `applyChanges` 재사용. 전문 머지는 순수 함수 `mergeProductEdits(detail, edits)` 로 분리해 esbuild 로 단위 시험.
- `components/coupang/CoupangProductDetailPanel.tsx` 는 커지므로 `CoupangProductEditPanel.tsx`(수정 모드) + `useCoupangProductEdit.ts`(편집 상태·변경 목록) 로 나눈다.
- 목록 칸 편집은 `components/coupang/CoupangInlineCell.tsx` 하나로 (숫자 입력 · Enter/Esc · 스피너 · 오류).

| 단계 | 내용 | 시험 |
|---|---|---|
| 1 | 목록 칸 편집 (A) — 프록시 추가 없음 | 운영에서 일반 옵션 1개 판매가 10원 올렸다 내리기 |
| 2 | 배송·반품 즉시 수정 (B) + 프록시 1개 | 일반 상품 1개 배송비 금액 바꿨다 되돌리기 |
| 3 | 재승인 수정 (C) + 프록시 2개 + 상세 패널 수정 모드 | **시험용 상품 1개** 노출상품명 끝에 한 글자 붙여 승인 흐름 확인 (승인대기 → 승인완료까지 지켜본다) |

| 5 | 하이브리드 노출상품명 | 3단계 결과가 로켓 채널에도 반영되는지 쿠팡 상품 페이지에서 확인 |

## 6. 위험과 보류
- **전체 PUT 의 미지수**: GET 응답에 들어 있는 읽기 전용 값(승인상태·노출상품 ID 등)을 그대로 보내도 쿠팡이 받는지 문서에 없다 → 3단계 시험으로 확인하고, 거부되면 그 칸만 빼고 보낸다.
- **승인대기 중 판매**: 수정 요청을 보내면 상품이 승인대기로 들어간다. 그동안 기존 승인본이 계속 팔리는 것으로 알지만 문서에 명시가 없다 → 시험용 상품으로 확인.
- **로켓그로스 옵션의 가격·재고·상태 API**: 문서에 언급 없음 → 4단계 전까지 로켓 옵션 칸 편집은 잠근다. 로켓 재고는 로켓창고 수량이라 API 로 못 바꿀 가능성이 높다.
- **이미지·상세 콘텐츠·고시정보**: 편집기(파일 올리기·HTML·카테고리별 고시 양식)가 별도 작업 규모라 보류. 필요하면 다음 계획으로.
